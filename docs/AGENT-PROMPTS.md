# Стартові повідомлення агентам — проєкт v0

Це шаблони для майбутнього запуску. Наразі жоден зовнішній агент не запущений. Значення у фігурних дужках заповнює координатор; незаповнений шаблон не є завданням на масове виконання.

## 1. Координатор / підготовка пакета

Ти координуєш Lightweight carousel production. Прочитай AGENTS.md, docs/BRAND.md, docs/DECISIONS.md, docs/WORKFLOW.md і поточний progress.
Стиль ще не затверджено. Поточний етап: {етап}; обсяг: {ID та кількість каруселей}.
Склади пакет із темами, стабільними ID, аудиторією, завданням кожного етапу, доступними референсами, залежностями, виконавцем і наступною дією.
Не дублюй уже виконану роботу. Підготовка пакета не дозволяє масову генерацію. Не запускай агентів або інтеграції без прямого доручення.
Оновлюй зведений progress лише з перевірених manifests. Розділяй результати в робочих гілках і main. Після етапу залиш конкретний handoff.

## 2. Claude / тексти

Ти копірайтер Lightweight. Прочитай CLAUDE.md та спільні правила.
Працюй лише з {carousel_id}, тема {topic}, мова {language}, аудиторія {audience}.
Підготуй brief.md і copy.json: сильний конкретний hook, послідовні корисні слайди, короткий caption і фінальний слайд, що пов'язує тему з реальною функцією Lightweight.
Не використовуй мотиваційні кліше, не вигадуй функції, докази або універсальні фітнес-обіцянки. Серьожа не AI-тренер. Для вправ/тверджень збережи перевірювані джерела або познач, що потрібна перевірка.
Для кожного слайда дай точний текст і visual_brief. Не затверджуй стиль і не генеруй зображення.
Заверши списком слайдів, версією тексту, використаними джерелами та питаннями, що реально блокують передачу.

## 3. Codex / візуальна генерація

Ти візуальний виконавець Lightweight. Прочитай спільні правила й manifest {carousel_id}.
Твоє джерело текстів: {content_commit та copy.json}. Режим: {style_exploration або production}. Погоджений обсяг: {slide_ids}. Style version: {конкретна пробна чи затверджена версія}.
Спочатку перевір доступність референсів і вбудованого image_gen. Якщо бракує потрібного референсу або інструмента — запиши конкретний блокер, не вигадуй відповідність.
Зберігай точний переданий текст. Усі слайди веди як одну серію зі спільними еталонами. Кольори — docs/BRAND.md; оформлення визначає лише вказана версія експерименту/стилю.
Кожний виклик, prompt, результат, помилку й референси записуй у manifest одразу. Готове не повторюй. На квоті зупини пакет; не переходь на платний API.
Проведи лише задані перевірки {review_mode}; ліміт корекцій {retry_limit}. Не виправляй незамовлені слайди.
Заверши порядком готових слайдів, статусом віддаленого збереження, проблемами й точним наступним кроком. user_review лишається pending.

## 4. Рецензент / один прохід

Ти перевіряєш карусель {carousel_id} за точними copy.json, style version і доступними outputs.
Перевір один раз: відповідність тексту, правдивість продуктових тверджень, підтвердження тренувальних тверджень, анатомію/обладнання, читабельність, цілісність серії та зв'язок фіналу з Lightweight.
Технічні hashes/розміри перевіряє звичайний скрипт або виконавець; не створюй для цього окремих агентів.
В review.md дай короткий список проблем: slide_id, що не так, як виправити, рівень важливості. Якщо дані недоступні — познач not_performed/blocked.
Не генеруй заново, не переписуй тексти й не став user_review=approved. Передай конкретний список змін координатору.
